# 盤面画像を毎ターン保存する

2026年10月16日。アプリ `0.1.0-preview.36`。

既存の `save_images` と `Simulation.visualize` を使い、画像保存を標準でオンにした。アプリとCLIは、各実験の結果フォルダ内に `img/step000.png` を作り、完了したターンごとに `step001.png`、`step002.png` と保存する。3桁は最小幅で、1000ターン目は `step1000.png` になる。

従来は初期値がオフで、オンにしても5ターンごとの `step_005.png` と `final.png` だった。新しい実行では最後の盤面も連番に含め、重複する `final.png` は作らない。既存の実験・画像は変更しない。

盤面は保存済みスナップショットを共通描画関数へ渡す。攻撃・被ダメージなどのイベント表情も画面と同じ状態になる。UIへ完了通知を出す前にPNGを保存するため、停止した実験にも完了済みターンの画像が残る。0ターンでも初期盤面を残す。

「保存設定」のチェックを外すか、CLIの `--no-images` で画像を省略できる。従来の `--images` も使える。プロンプト、モデル、行動ルール、乱数処理は変更していない。

開発コードは `~/Documents/dev-llm-sugarscape/` へ非公開リポジトリから復元した。使用するアプリは `/Applications/LLM SugarScape/LLM SugarScape.app`。公開用の素材は `~/Documents/llm-SugarScape/img/` に戻し、公開リポジトリの `main`（`2adaafa`）へ保存した。17ファイルのGit blob SHAとサイズを公開先で照合済み。

盤面上の個体番号は7ptから13ptへ拡大し、太字・白い背景を付けた。共通描画関数の変更なので、ライブ盤面、保存済み実験の表示、PNGのすべてに反映する。

現在ステップの伝達も確認した。標準設定では個体の年齢 `cycles` と過去3ターンの記憶を渡すが、現在の世界ステップは明示しない。`provenance` を有効にした場合だけ `Current Observation (Step N; source: environment)` を付ける。2026-10-16 00:36:57のオフ会実験では同設定が無効で、Step20の入力は `cycles: 19` とStep17〜19の記憶だった。この確認に伴うプロンプト変更は行っていない。

## 検証

- Python 3.11.14で全216件のテスト成功。画像保存、停止・全滅・0ターン、CLIの初期値とオフ指定、イベント表情と画面描画の画素一致、UIの保存先変更を確認した。
- 通常のアプリと同じPython 3.11.14のstandaloneビルドを作り、同梱ランタイム、アドホック署名、配布ZIPを検証した。復元時に最初に使ったHomebrewのframework版Pythonは既存の配布検査と形式が異なったため、従来のpyenv環境に揃えて再作成した。
- `/Applications/LLM SugarScape/LLM SugarScape.app` に更新版を配置し、画面の版番号36と画像保存の初期値オンを確認した。通信しないMockを1ターン実行し、`step000.png` と `step001.png` の実ファイルを確認した。実行IDは `20261016T014137507607Z_0_71d5dd59`。
- 既存のオフ会実験を再表示して拡大した番号を実画面で確認した。動作モード、保存先、更新前の世界観と実験条件を戻した。LLMへの実験要求は送っていない。
- 通常の保存先は従来どおり、アプリ横の `outputs` から公開用checkoutの `log/yuki1/` へつながる。Mockの検証記録は非公開の開発用出力に保管する。

開発コードの変更はローカルで保存し、公開用リポジトリへ送信したのは指定された `img` の素材だけ。旧アプリは開発checkoutの `build/installed-preview35/` に保管した。
