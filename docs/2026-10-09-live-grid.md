# 2026-10-09 実行中の盤面表示

既存のスナップショットを描画し、Streamlitに開始時（Step 0）と各ターン終了時の盤面を表示する。全個体の判断を集めて行動を適用した時点で更新するため、応答待ちの間は直前の盤面を保持し、横に届いた発言を表示する。

終了後もステップ選択で盤面と会話を見返せる。位置・エネルギー・餌・死亡時点は保存された記録を使い、表示のためのLLM要求やシミュレーションの再実行は行わない。

## 色とマーク

繁殖コストを `C` とする。この変更時点の初期設定は `C = 70`。その後の[論文プロトコル復元](2026-10-09-paper-protocol-restoration.md)で `C = 150` に変更した。

| 表示 | 条件 |
| --- | --- |
| 青 | エネルギーが `C` 未満 |
| 緑 | エネルギーが `C` と同じ |
| 緑から黄色へ | `C` 以上・`2C` 未満。エネルギーが増えるほど黄色に近づく |
| オレンジ | `2C` 以上。初期設定なら140以上 |
| ピンクの四角 | 餌 |
| × | 前のターンで死亡した個体 |

×は死亡ターンの次のターンだけ表示し、その次には消える。例えばStep 2で死亡するとStep 3だけに表示する。最終ターンで死亡し、次のターンがない場合は×を表示する追加ターンを作らない。

数字は個体ID。同じマスに複数の個体がいる場合は、マス内でマークを少しずらす。Y座標は上から下へ増え、北への移動（Y−1）が画面の上方向に対応する。色はエネルギー基準であり、人口上限による繁殖の可否は行動結果で確認する。

## 実装と検証

`grid_view.py` の描画処理を実行中・履歴・保存画像で共用する。表示へ渡す状態をコピーし、乱数や保存記録を変更しない。既存の記録形式・行動順序・エネルギールールは維持する。

`env MPLCONFIGDIR=.mplconfig .venv/bin/python -m unittest discover -s tests -v`：43件成功。移動後の位置が初期状態から各ターンの表示へ渡ること、表示側の変更が保存記録に影響しないこと、色の境界、餌の位置、重なり、死亡の翌ターンだけの×、画面のStep 0と会話切替を検証した。

Chromeの別タブで5個体・3ターンのMock実行を行い、盤面・ピンクの餌・オレンジの個体・凡例・履歴選択を目視確認した。Mockは待機のみのため、移動と死亡のタイミングは制御した状態を使うテストで確認した。確認データは `outputs/grid-ui-validation/2026-10-09_15-44-42_Mock/` に保存した。
