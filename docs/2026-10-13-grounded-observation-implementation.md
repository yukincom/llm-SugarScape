# 観測・記憶・実行の段階実装

2026年10月13日。[設計案](2026-10-13-grounded-observation-design.md)に基づく実装記録。UIと世界ルールを維持し、入力への変更を独立した比較条件にする。モデルへ送るプロンプトは実験前にユーザーが確認する。以下の自動検証では固定応答や通信の代替を用い、実モデルは呼び出していない。

## 第1段階：入力を変えずに観測・実行を記録

- 資源の追加生成後、全員の判断前の世界状態を監査用に保存する。各個体の観測は変更不能な値として先に確定し、実験ID・ターン・個体IDで応答へ結び付ける。
- 現在のLocal View、自己状態、従来の記憶・受信文を観測に保持する。世界全体の状態は監査専用で、プロンプトへ追加しない。
- 実行直前に行動に関連する値を記録する。変化の有無は監査だけに使い、既存の行動条件や拒否判定を増やさない。
- 自己行動直後とターン終了時の値を分け、実行結果と本人のThought先頭100文字を直近3件の内部履歴に保持する。従来の画面用記憶文字列は変えない。
- メッセージ本文と実際の送信者・生成／配送／読取ターンを別々に保持する。本文、配送範囲・タイミング、新生個体への配送は維持する。
- 保存schemaを6、engineを5.2にする。旧schema 1〜5の読取と版別CSV列を保持する。新しい入れ子の観測・実行結果は既存JSON記録とevents.csvへ保存する。

復旧基準は `67183a777cdd6171d36619f1b09d22b3cac28420`。同じ応答列を使い、10シード×20ターンで旧版と比較した。**210スナップショット、1,491判断の全既存フィールドと送信プロンプトが一致し、世界・性格の乱数状態も一致**した。これは実行規則と入力の互換性の確認であり、モデルの行動改善を示す結果ではない。

比較処理・結果は 検証フォルダ（`outputs/validation/2026-10-13-grounded-observation/`、当時のローカル検証資料・公開対象外） の `compare_baseline.py`、`stage1-baseline-comparison.json` に保存する。

観測専用10件を含む関連77テストが通過。観測後の資源競合、遅いIDからの攻撃、送信者の偽名、相対座標、HTTP失敗、旧CSVの列を確認した。レビューで自己状態・記憶の参照も固定観測に統一し、判断待機中に可変状態が変わるケースも追加した。記録は同フォルダの `stage1-tests.log`。

## 第2段階：独立した入力条件

第1段階のチェックポイントは `a5e31ca`。既存の `DEFAULT_PARAMS → Simulation → build_prompt` に `prompt_factors` を追加した。既定は空で、従来のプロンプトを維持する。選択条件は出生個体にも引き継ぐ。本文と設定は既存の実験記録へ残り、protocolのIDと有効条件を明示する。

| 条件名 | 単独で変わるもの |
| --- | --- |
| `provenance` | 現在観測・過去の自己記述・実行記録・受信文を出所付きにする。送信者と時点は本文の外側に付け、本文は変更しない |
| `relative_coordinates` | Local ViewのMを(0,0)へ統一し、座標説明を置換する。自己の絶対位置はStatusに残す |
| `action_outcomes` | 前3回の自己行動の実結果を追加。拒否、形式補正、自己行動直後とターン終了時の体力を区別する |
| `action_last` | 既存の3項目と説明文を維持し、Thought → Message → Actionの順にする |
| `grounded_thought` | Thoughtの説明だけを、現在の根拠と意図を短く確認する文へ置換する |

5項目は任意に組み合わせられる。全32組合せへ同じ固定応答を与え、世界状態、既存の画面用データ、出生・配送・行動結果、乱数状態が一致することを確認した。関連85テストが通過し、`stage2-tests.log`へ記録した。実モデルに対する効果は未測定。

## 第3段階：通信なしでプロンプトを確認

第2段階のチェックポイントは `9f4fa80`。`Simulation.preview_next_prompts()` は世界と乱数を複製し、実験と同じターン境界・観測・生成処理で次の入力を作る。元の世界は進めず、通信・接続確認・モデル識別・実験記録の開始は行わない。最初の入力は、実行と共通の設定検証を使う `preview_prompts(params)` で出力できる。

既存の `main.py run` に `--prompt-factor`（複数指定可）と `--preview-prompts PATH` を追加した。後者がある場合は実験へ進まず、初回入力をJSONへ保存して終了する。既存ファイルへの上書きは拒否する。視界・通信範囲もコマンドから指定できる。画面の設定項目や組み込みプリセットは変更していない。

次は**無通信で確認用ファイルだけを作る**例。`--preview-prompts` を外すと実験になるため、プロンプト確認前には外さない。

```sh
.venv/bin/python main.py run --agents 4 --steps 30 --seed 42 \
  --grid-size 15 --initial-energy 20 --child-initial-energy 20 \
  --population-cap 4 --spawn-energy-count 2 --num-clusters 2 \
  --cluster-radius 0 --energy-spawn-rate 0 --view-range 3 --message-range 7 \
  --prompt-factor provenance --prompt-factor relative_coordinates \
  --prompt-factor action_outcomes --prompt-factor action_last --prompt-factor grounded_thought \
  --preview-prompts outputs/review-grounded.json
```

人間向けの[確認資料](2026-10-13-grounded-prompts-review.md)と[全条件の原文JSON](data/2026-10-13-grounded-prompt-previews.json)を保存した。基準・5単独条件・全併用を、既存の霧プリセットの初回と、固定応答から作った履歴ありの場面で示す。計42入力を同じ生成処理から出力し、84個の原文ハッシュを照合した。履歴中の発言は人工例であり、実モデルの挙動ではない。再出力は `tools/preview_grounded_prompts.py NEW_REVIEW_DIRECTORY` を使う。

## 最終検証と未実施の範囲

- 全体の **180テストが通過**。プレビュー5件は、接続処理へ進まないこと、元の状態と乱数を変えないこと、次ターンで実際に作るプロンプトとの一致、選択条件の記録、ファイルを上書きしないことを確認した。
- 最終状態でも旧版との210スナップショット・1,491判断の比較が一致した。既定条件のプロンプトと世界の乱数状態を含む。記録は検証フォルダの `final-default-comparison.json` と `full-tests.log`。
- 5条件の全32組合せについて、同じ固定応答を使った世界・表示用データ・乱数の一致を確認した。これは入力条件によるエンジン変更がないことの検証であり、モデルの認識・判断の改善を測ったものではない。
- `app_ui.py`、`app_presets.py`、`agent_view.py`、`grid_view.py`、`translations.py`、`response_fields.py` は設計時のコミットから変更していない。画面の自動テストも通過したが、デスクトップ実機での差し替え後の確認は行っていない。

自動的な長期記憶更新、被攻撃者への相手通知、他者の非公開情報、行動の最適化は今回追加しない。デスクトップアプリの差し替えとLLM実験は未実施。
