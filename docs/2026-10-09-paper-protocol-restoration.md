# 2026-10-09 論文付録A1のプロンプトと処理系の復元

## 問題と修正範囲

旧実装は付録A1の状況要約・思考と感情・Memoryの指示を消去し、Action / Message / Thoughtの3項目へ変更していた。Thoughtの一部をコード側で記憶として作り、Share / Attackを移動・待機・繁殖と排他的に処理していた。この状態は原文のプロンプトの再現ではなかった。

[Masumori and Ikegami, arXiv:2508.12920v1, Appendix A1/A2](https://arxiv.org/html/2508.12920v1#A1)を照合し、System本文とUserの指示全文を`paper_prompts.py`へ保存した。原文はCC BY 4.0。改行は正規化し、例示された個体の状態・過去の記憶は固定指示として使わず、各個体の実際の値に置き換える。

- Summary、Thoughts、Next Action、Share、Attack、Message、Memoryの7項目を要求・解析・保存・表示する。Share / Attackは任意。
- 要約・思考と感情・発言・記憶の複数行を保持する。Memoryはモデルが出した全文を直近3ターンだけ次の入力へ渡す。失敗ターンでも時間が経過し、古い記憶は残らない。
- 原文のMessage 250文字／Memory 1000文字の指示を残す。超過した応答をコードで切り詰める処理は加えない。原文には超過時の扱いが記載されていない。
- Next Actionは上下左右1マス／待機／繁殖の1つ。Share / Attack / Messageは別々に実行する。
- 繁殖コスト150、送信費用1、攻撃で相手を死亡させ全体力を移す。移動2・待機1・砂糖取得50を維持する。
- A2に合わせてTemperature 0.7、max_tokens 10000、top_p 1.0を既定値にする。
- 本文に合わせて世界30×30、視界5×5、通信7×7にする。ユーザー指定の開始・出生時体力100とMBTI既定オフを維持する。

schema_version=3、engine_version=3.0とし、7項目・操作別の実行状態・費用・受信者ID・記憶を保存する。manifestには出典、原文内部の食い違い、採用した実装選択とソースのハッシュを記録する。schema 1・2の既存結果も読み返せ、旧形式のCSV列を維持する。過去の結果と同梱サンプルは書き換えない。サンプル生成スクリプトだけ新しい解析形式に対応させ、従来サンプル用の独自条件（体力150・繁殖コスト70）を明示する。

## 原文内部の食い違いと今回の判断

- 死亡：本文は体力0、A1 Systemは0未満。ユーザー指定に従い、1は生存・0以下は死亡とし、実行時Systemの対応箇所も置き換える。
- 攻撃範囲：A1 Systemは視界内、Userは隣接。ユーザー指定に従って上下左右の隣接を使い、Systemの対応箇所も置き換える。
- 相手の移動：全員の判断時点であるターン開始時の位置で隣接を判定する。適用順で先に相手が移動しても範囲外にはしない。視界に入るだけでは攻撃できない。
- 視界と通信：本文は5×5視界・7×7通信。A1の例は距離3の対象を含み、Systemは通信も視界内と記載する。指示文を削らず残し、実行範囲は本文を採用する。この差はmanifestにも記録する。

## 論文だけでは確定しない実装と残る差

ID順にNext Action→Share→Attack→Messageを適用し、共有可能な体力は先行操作後の値で判定する。途中で死亡した個体の残りの操作は実行しない。既に送った発言は、送信者が同じターンに死亡しても生存する受信者へ届ける。共有履歴は相手ID別の累積送付量として扱う。境界はトーラス、出生位置はランダムな上下左右の隣接マスである。

砂糖配置は既存の正方形クラスタ内での一様抽出と追加確率を維持しており、論文の二重ガウス分布ではない。LLMのモデル・実行環境、個体数・ターン数・試行回数も原研究と異なる。プロンプトと対応処理の復元を、論文全実験の厳密な再現とは扱わない。
